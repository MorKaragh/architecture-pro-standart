**Архитектурное решение:**

*Набор компонентов:*

1. **Сайт банка** - расширение существующего сайта на PHP/React.js для отображения кредитных предложений и приема заявок
2. **Интернет-банк** - доработка существующего ASP.NET MVC приложения для работы с кредитами
3. **API Gateway** - существующий компонент, точка входа в backend для различных интерфейсов
4. **Сервис аутентификации и авторизации** - существующий компонент для аутентификации и авторизации
5. **Сервис кредитных заявок** - новый микросервис для обработки заявок на кредиты, их жизненного цикла и кросс-канальной работы
6. **Сервис персональных предложений** - расширение существующего (разработанного в рамках депозитного процесса) сервиса для расчета предодобренных кредитных предложений на основе данных клиента из АБС
7. **Сервис уведомлений** - существующий микросервис для отправки SMS и функциональности подтверждений
8. **CRM** - существующий модуль для ведения клиентской базы и кросс-канальности заявок (на платформе колл-центра, внедрен в рамках депозитного процесса)
9. **Адаптер к АБС** - существующий компонент, интеграционный шлюз к АБС
10. **АБС** - доработка для работы с заявками с сайта и интернет-банка
11. **Кредитный конвейер** - существующая система для обработки заявок на кредит, доработка для публикации событий заявок в брокер сообщений
12. **Система кредитного скоринга** - существующая система для определения рейтинга клиента
13. **Бюро кредитных историй** - внешняя система для получения данных о клиентах

*Основные принципы решения:*

- Использование существующей архитектуры депозитного процесса с добавлением кредитной функциональности
- Интеграция с существующими системами кредитного скоринга и кредитного конвейера
- Поддержка кросс-канальности: клиент может подать заявку на сайте, а продолжить в отделении, или сразу начать в отделении
- Предодобренные предложения для клиентов интернет-банка на основе данных из CRM и кредитного конвейера
- Заявка из цифровых каналов может двигаться по своему жизненному циклу не дожидаясь синхронизации с АБС

*Технологические решения:*

- **Сервис кредитных заявок**: Java Spring Boot, интеграция с существующей архитектурой
- **Расширение сервиса персональных предложений**: добавление логики расчета кредитных предложений
- **Внедрение брокера сообщений для статусов заявок**: Kafka в качестве брокера сообщений для трансляции событий по заявкам (в первую очередь смены статусов)
- **Мониторинг**: интеграция с существующей системой мониторинга
- **Логирование**: централизованное логирование через ELK

*Процесс работы:*

1. **На сайте**: клиент видит предложения, заполняет заявку, при вводе паспортных данных происходит авто скоринг через БКИ
2. **В интернет-банке**: 
   - Сервис персональных предложений получает данные клиента 
   - На основе истории операций, балансов и других данных клиента рассчитываются предодобренные предложения
   - Клиент видит персональные предложения и может подать заявку с подтверждением SMS
3. **Обработка заявок**: заявки передаются в кредитный конвейер через API, где происходит (повторный) скоринг и принятие решения
4. **В отделении**: сотрудник может продолжить работу с заявкой, поданной онлайн, или создать новую в АБС
5. **Уведомления**: клиент получает SMS о статусе заявки на ключевых этапах

### **Альтернативы**

**Альтернатива 1: Прямая интеграция сайта и интернет-банка с кредитным конвейером**
- Преимущества: Простота реализации, меньше промежуточных компонентов
- Недостатки: Нарушение принципа единой архитектуры, сложность поддержки кросс-канальности

**Альтернатива 2: Создание отдельной системы для онлайн-кредитования**
- Преимущества: Полная изоляция от существующих систем
- Недостатки: Дублирование функциональности, сложность интеграции с АБС

**Альтернатива 3: Использование только системы кол-центра для всех заявок**
- Преимущества: Единая точка обработки заявок
- Недостатки: Перегрузка системы кол-центра, ограниченная автоматизация

**Недостатки, ограничения, риски**

**Недостатки:**
- Увеличение сложности архитектуры за счет интеграции с дополнительными системами
- Дополнительные точки отказа в системе
- Необходимость синхронизации данных между системами

**Ограничения:**
- Зависимость от производительности системы кредитного скоринга
- Ограниченная возможность изменения процесса работы кредитного конвейера
- Синхронизация данных между кредитным конвейером и АБС раз в сутки

**Риски:**
- Технический риск: сложность интеграции с существующими системами кредитования
- Операционный риск: необходимость поддержки дополнительных интеграций
- Риск производительности: перегрузка системы скоринга при массовых заявках
- Риск синхронизации: расхождение данных между системами при сбоях передачи
- Риск ИБ: передача чувствительных данных через внешние API (БКИ)
